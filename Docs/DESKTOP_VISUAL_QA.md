# VR exhibit pose-emulation verification

The original filename is retained for existing links. There is no separate desktop UI: all canvases are world-space, and keyboard/mouse emulate visitor/head and wrist poses for the same exhibit.

Unity Editor **6000.3.25f1 (Unity 6.3 LTS)**, URP 17.3.0, Input System 1.17.0, UGUI 2.0.0. The scene is visual staging; the separately tested inspiral model is not bound into its positions or graph.

## Run

1. Add `BinaryBlackHole` in Unity Hub with Editor 6000.3.25f1.
2. Open `Assets/DTET/Scenes/BinaryBlackHole_VisualStaging.unity` and press Play.
3. Right-drag to look, WASD to move, Q/E for height, Shift for faster movement, wheel for forward/back. **V raises/lowers the virtual wrist**; left-click its controls. No screen toolbar is shown.
4. T approaches spatial information panels; H opens and approaches the physical learning board. Try Story / Graph / Model, A / B, separation followed by Apply Start, seek, playback rate, quick check, and dimming. Wrist controls remain available beside the learning board. H hides the board; F/Home returns to the event. Space toggles playback, Esc pauses, R resets, B dims, U toggles the whole partner interface, C selects optional orbit inspection, and 1/2/3 select learning layers.
5. **DT-ET > Validate Assets and Build QA Player** validates the scene and all **five** custom shaders, then builds `BinaryBlackHole/Builds/VisualQA/BinaryBlackHole_VisualQA.exe`.

## Automated checks

Set `DTET_CAPTURE_PATH` and optionally `DTET_CAPTURE_VARIANT` before running the development player. Variants: Options, Lensing, LensingOff, Wrist, Hud, HudEnd, Observe, Above, Side, Close, Clocks, Story, Graph, Model, Endpoint, ScenarioB. The harness is excluded from release builds and only activates when a capture path is set. Screenshots require a rendered window; a fresh nonempty PNG is checked before success is reported. K approaches the future clock comparison card; F returns to the exhibit. J approaches approximate lens alignment, L compares bending off/on, G toggles broken-ray guides, and O opens/closes wrist input options. Captures use in-memory default sensitivities without overwriting saved preferences.

- Learning callbacks: layers, scenarios, pending/apply separation, reset/seek, formative feedback, dimming.
- Camera commands: perspective, viewpoints, body focus, bounded orbit zoom, finite extreme input, free movement, recoverable visitor pose, full viewport beside the learning board.
- Input System events: mouse look, wheel locomotion/suppression over wrist UI, optional orbit mode, movement/height, viewpoint recovery, learning transitions, and focused-body tracking through seek.
- Partner commands: shared playback state, rate cycle/clamps, two-way learning-slider synchronization, unavailable physical values, playback time, conceptual endpoint narration, and visibility.
- Wrist/world input: V raise/lower, world-space-only canvases, wrist parenting, projected pointer targeting/click, gaze-independent wrist pose, visitor translation carrying the arm, and wrist availability beside the learning board.
- Model regression: `dotnet run --project Staging/Simulation.Tests/BlackHole.Staging.Simulation.Tests.csproj -c Release`. These tests do not establish Unity-model integration.
- Stellar/clock foundation: fixed source object identities and positions, one batched renderer, geometric parallax and unbent image centres; unavailable clock values, epoch/worldline invalidation, sign conventions and staging labels. These tests do not establish relativistic optical accuracy. See [optics and clocks](OPTICS_AND_CLOCKS.md).
- Approximate lensing: multiple and deflected background images, changing apparent direction during navigation, fixed source objects, unchanged rest colours, broken-ray guides, direct-image restoration and LENS/RAYS/ALIGN wrist callbacks. Source tests additionally check the actual lens equation, five-image binary fixture, analytic single-lens roots and Jacobian. See [approximation limits](APPROXIMATE_LENSING.md).
- Input options: actual pointer opens wrist options and changes the look slider, independent scroll slider callback, wheel suppression over the menu, reset/slider synchronization, O return, default 2.4-unit wheel movement (3× the original), optional orbit scaling and independent look scaling. The portable settings tests cover clamps/nonfinite rejection. QA does not write saved preferences; persistence across a real restart and manual usability remain separate checks. See [input options](INPUT_OPTIONS.md).
